# Steam 研究的决策口径

2026-10-25。目标是帮助独立开发者 / 小团队选择下一款游戏的验证切入口，不是预测销量或复制榜首。新站保持 App Store 功能；Steam 在同站作为独立研究工作台。原 appgap.01mvp.com、D1、mybros 与 Mini Tanks 运维不改。

## 证据与覆盖

- 按 Steam 官方实时畅销页当前公开提供的全部区域抓取，每区原始前 100 项，另保留全球榜；本次源列出 29 个区域。记录地区代码、原始名次与可用的上一期官方周榜基线日期，剔除 DLC / 软件等非完整游戏，但不把剩余游戏重新编号。
- 区域内免费游戏来自本区完整畅销榜里的免费条目；额外使用全球免费游戏畅销排序与全球最常玩前 100。Steam 没有公开各国「免费下载量榜」；不能把免费游戏畅销排名、最常玩或区域商店搜索结果叫做下载量。
- 收入排名来自全部收入来源，含 DLC / 内购，免费游戏也能有收入。实时名次是序数；不按名次推算金额、销量或不同国家的市场规模。
- IStoreBrowseService/GetItems 提供公开商店元数据、官方标签、发行信息、USD 参考价、折扣和公开总体评价摘要。它是商店自身使用的公共接口，但不属于稳定的文档化合作伙伴接口，版本或字段变化必须显式报错。地区表的本地价格仅保存原格式，跨区对比使用同一 USD 参考价。
- 评论使用新官方 IUserReviewsService/GetAppReviews，旧 /appreviews 已被官方标记废弃，现场验证会跳转商店首页。每款游戏取最近 30 天最近至多 100 条全体评论，另取至多 50 条负面评论；重复 recommendationid 去重，保留时间、语言、购买来源 / 免费获取 / 退款标记及原评论链接。负面样本比例仅表示「抽中的负面评论中出现该主题的比例」。语言不能等同于居住国家。
- 仅使用匿名公开接口；不使用 Steamworks 发行商密钥，不绕过年龄、账户、付费或反爬访问限制。源可能对匿名访客过滤部分内容，榜单也有幸存者偏差，不构成全 Steam 游戏总体。

## 比较方法

1. **谁在付钱**：观察实际入畅销榜、定价方式、正常价 / 折扣、地域覆盖及持续入榜。免费不等于没有付费，评论量不等于销量；购买评论者样本不等于全体付费玩家画像。
2. **谁被骂**：将整体口碑与有日期限制的近期评论样本分开。关键词匹配只是可核查的主题线索，不代表情绪因果，也不当作真实翻译。默认过滤源标记的离题评论，保留可追溯短摘录和样本量。给出近期全体样本差评比例的 Wilson 区间，同时明确最近 N 条不是随机抽样，区间不覆盖抽样偏差。
3. **哪类玩法在涨**：以源给出的上一期周榜为基线，与本期实时名次比较；显示基线日期、重叠样本数和缺失。日后用每天保存的紧凑排名历史形成 7 / 28 天序列；第一天不能伪造长期增长曲线。新入本期榜不等于新发布。
4. **国家 × 类型**：以官方标签形成可筛选的游戏群组；标签互相重叠，不能把格子的百分比相加。显示该类型在本区已采集游戏中的 n/N、相对全球样本入榜率及有效样本数；不把样本入榜率当作市场份额或玩家规模。
5. **机会与可执行性**：分别呈现需求线索、重复痛点、动量与开发范围风险。优先级是可解释的研究排序，不是成功概率；MMO / 大世界 / 竞技生态的运维成本和用户迁移成本必须惩罚，Indie 标签不能证明团队人数。
6. **综合论证**：以多款可对照游戏、多个区域、来源评论及反例形成假设；列明差异化、原型范围、目标人群、验证指标、停止条件与替代解释。定价 / 发行阶段 / 节日折扣可能造成短时上涨，不能都归因为新玩法需求。

## 新鲜度与验证

Steam 每日香港时间 09:00 更新；网站只读已完成缓存。采集状态单独呈现，不在网页请求时现场抓 Steam。至少 90% 区域榜成功且元数据通过结构验证后才发布；失败保留上一份快照，并显示缺失与错误。评论覆盖单独列出，不将获取失败当作没有差评。原始响应、SHA256、请求 URL 与采集时间保存在服务器自己的 raw 目录；完整快照保留 7 期，紧凑排名历史保留 400 天。

公开源与方法优先级：Steam 官方定义 / 公开源 > 现场响应结构 > 社区协议跟踪 > 开源示例与社区研究。社区的评论倍率收入估算和自报 ROI 只可作研究假说，不作为事实输入。具体源码、维护状态和采用 / 不采用的理由在研究报告补充。
