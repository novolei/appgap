# AppGap 深度审计与独立部署

核查基线：`1e8477a`；2026-10-25；本地 `G:/MyTools/appgap`。按个人 / 小团队内部工具、单台 VPS、单个 Web 进程和一个定时采集进程评估，不按多租户 SaaS 设计。

这个仓库从 Apple 公开榜单、Lookup 和评论接口整理工具 / 游戏需求线索，支持候选、立项、Markdown 导出及可选 DeepSeek 分析。原实现是 React + Hono + Workers + D1；本轮为 `appgap.if2.ai` 增加 Node 24 + SQLite 独立运行方式，保留原 Workers 配置和原站数据，不在原站部署这些改动。

## 必须修复，已处理

1. **锁的检查与写入分离，两个采集会同时开始**（`src/worker/ingest.ts`）。原来两个调用都能先读到「没有 running」，再分别写 running，随后互相清 staging。增加数据库唯一 running 索引，以插入是否成功作为最终判据；并发回归证明只允许一个成功。若不处理，网页会展示两个采集混在一起的结果。
2. **失败的刷新可能损坏当前快照**（同上）。原实现先删除本期排名、分批写入，错误时只保留 opportunities；读接口却按 MAX(snapshot_date) 读取排名，出现半份新榜单与旧机会混用。现在应用、排名、评分都先写 staging，最后与机会和成功状态一起事务提交；注入最终 INSERT 失败后，所有已发布表保持旧值。
3. **国家筛选会把免费第一名当作畅销第一名**（`src/worker/app.ts`）。原国家子查询只按 app/country 分组；同一 App 免费第 1、畅销第 38 时，畅销列表显示第 1。现在按 chart / genre 对齐，回归要求得到 38。
4. **会话在服务端永不过期**（`src/worker/auth.ts`）。原 cookie 是全站口令对固定文本的 HMAC，Max-Age 只约束浏览器，复制出的 cookie 可以无限重放。改为签名覆盖过期时间并在服务端检查；测试覆盖到期、篡改、换密码。新 VPS 还限制登录尝试、请求体大小、跨来源写入，禁止公开采集入口；localhost 采集放行只在专用本地 Wrangler 配置显式启用。
5. **坏输入会 500 或误删收藏**（`src/worker/app.ts`）。`appId:123` 会对数字调用 trim，漏传 pool / pool:false 又会落入删除分支。现在严格检查对象、数字字符串 ID 与 pool；只有显式 null 才删除。测试确认坏输入不会清掉原立项。
6. **已锁定 Hono 版本存在五项中等风险公告**（锁文件及依赖审计）。已从 4.13.3 更新为 4.13.13；生产依赖审计为 0 项。公告包括查询解析差异、静态路径二次解码及不受限的表单嵌套；没有把「公告存在」冒充为本应用已经可被这些方式利用。证据：`output/dependency-audit.json`（本地忽略文件）。
7. **跨市场评分混用会制造错误的差评机会**（`src/worker/ingest.ts`、`src/shared/classify.ts`）。某国 Lookup 失败时，原逻辑借用其它国家评分并标为该国。现在跨市场只能补充应用描述，评分保持缺失；分类评分索引也只认同一国家。
8. **免费榜被写成收入已验证、好评分也被预设成口碑差**（`src/shared/analysis.ts`）。现在明确区分免费 / 畅销线索，不推断收入数字，标题改为中性摘要。添加免费榜高评分样本，防止重新产生误导结论。

## 已完成的优化

9. **40 项后的收藏静默消失**（`src/client/api.ts`）。服务端每批上限 40，前端原来只发一批。现在分批读取并合并；85 项样本确认三批全部返回。AI 请求返回时也检查当前 App，避免切换详情后把上个 App 的分析写到下个 App。
10. **采集请求过多、慢请求没有截止时间**（`src/worker/apple.ts`）。Lookup 每批由 10 增至 100、明确 limit=200，并将 Lookup 起始速率控制在约每 3 秒一次；国家间有限并发，所有 Apple 请求有 15 秒超时。这减少请求数量，不保证 Apple 永不拒绝。采集成功还要求至少 90% 榜单非空，防止把抓取失败当作「别国没有」。
11. **重复扫描全量排名 / 评分拖慢分类**（`src/worker/ingest.ts`、`src/shared/classify.ts`）。原来每个 App 都 filter / sort 全部排名、find 全部评分。改为一次构建按 App / 国家索引，保持原分类规则；历史窗口由 30 天扩至一年，使每周连续出现次数不再一个月就截断。快照日期统一为香港时间，与定时器一致。
12. **运行方式只适合 Workers，本机采集脚本混有 macOS 假设**。新增官方 Hono Node 适配器和 Node 内置 SQLite 适配；prepared bind 独立、batch 原子事务均有检查。VPS 用 systemd 定时采集，不启动生产环境的 Wrangler dev，也不依赖个人电脑在线；Web 只绑定回环，独立用户、内存 / CPU 限制，版本目录切换与健康检查回滚。备份使用 SQLite 在线备份接口，不直接复制活动 WAL 数据库。

## 后续建议，未扩大本轮范围

13. **词表不是翻译，游戏也不能套用工具分类**（`src/shared/translate.ts`、`src/worker/detail.ts`）。已修复 Games 类目被描述中的 cleanup 等关键词误标为手机清理的问题，保留游戏原名、限制游戏分类，并让 AI 读取商店介绍和原评论。词表改变正文时保留原文，不将词表整理作为模型的唯一证据；原 App Store 分析缓存换版本，不沿用错误标签产生的旧报告。词表结果仍不能代替真正翻译进行决策。
14. **AI 缓存与预算已补齐**（`src/worker/ai.ts`、`src/worker/analysis-cache.ts`）。现场可用模型为 deepseek-flash；显式关闭默认思考，正文最多 8,000 tokens，拒绝缓存截断结果。App Store 与 Steam 共用持久缓存、相同请求合并和每日 20 次新请求额度；App Store 的 fresh 参数不再绕过有效缓存。标准报告保存 7 天，自定义研究按签名会话隔离、缓存 24 小时。已实际生成 Steam、App Store 和私有研究并验证重复读取。真正的账号身份、用户级余额和美元预算仍为下一阶段；不冒用其它项目的 Key。
15. **历史与数据展示仍有口径限制**。连续出现次数是扫描次数，不是自然天；离榜后回来仍可能被「新上榜」选中；不同国家 / 日期的 Apple 本地化名称合并后只有一个 App 名称。建议记录首次见到日期、逐市场快照覆盖情况和本地化名称；「不在榜上」始终不等于「该国未上架」。
16. **评论缓存 / 客户端容错仍可改善**（`src/worker/detail.ts`、`src/client/App.tsx`）。详情无评论会现场请求 Apple，已有评论没有按年龄失效；切换 Hash 的浏览器前进后退没有监听；收藏初始化错误被吞掉，旧 localStorage 名单中途迁移失败后可能留下一半；复制 / 收藏按钮失败缺少就地提示。下一轮应先补这些真实流程的浏览器测试，再改交互，避免一次引入新框架或重写页面。
